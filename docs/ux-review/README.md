# edot — First-Time-User UX Review (June 2026)

A structured usability sweep of the **edot** office suite (`magpie/edot/index.html`), run as a multi-agent exercise: one encapsulated subagent per app played a **first-time user with no prior knowledge** ("someone told me it's an office tool, try it"), drove a real headless Chromium (desktop 1280×800 + mobile 390×844 touch), attempted 2–3 realistic tasks, screenshotted and visually inspected each step, and wrote an honest review. ~22 use cases across 9 areas.

**Method note:** agents judged only what was *visible on screen* — they did not read the source to learn intended behaviour. Findings are observation-based. Headless WebGL/tiles are limited in this sandbox (SwiftShader ~2fps; OpenFreeMap tiles did not load), so anything tile- or perf-dependent is flagged as unverifiable rather than asserted.

## Cross-cutting themes (appear in 3+ apps)

1. **Mobile "Workspace" nav item is zero-width / unreachable.** Reported by Shell and Backup; the bottom tab bar collapses Workspace to 0px. A phone user can never reach the home view.
2. **Mobile toolbar overflow clips controls off-screen with no scroll affordance.** Data (`scrollWidth 847px`), Maps (Import/Export/KML at negative x), Slides (Indent clipped), Editor (dense 4-row wrap). Features become unreachable on phones.
3. **Silent failures — actions that fire with no feedback.** Editor link button (no dialog), Maps blank canvas (no loading/error state), Data welcome cards dead during WASM init, Automations Run (log invisible/cleared), Mail Send (tiny grey error). Users conclude "it's broken" when it often isn't.
4. **Weak zero-state / onboarding.** Workspace tri-panel with no explanation, Mail empty inbox with no copy, Automations no plain-language intro, Backup no statement of what's included or a local-export path. New users lack a mental model of what they're looking at.
5. **Naming/jargon mismatches.** Editor "View" menu actually holds paragraph styles; Maps "Pins" button vs "Saved Places" panel; Maps basemap labels expose renderer jargon ("OSM (raster)", "vector"). 
6. **Touch-target sizes below 44px** on Editor (35×35) and Backup rail (39px wide).

## Confirmed blockers (fix first)
- **Mail → Send** throws `Cannot read properties of null (reading 'sendMessage')` every time (desktop + mobile).
- **Editor → Insert link** produces no dialog and no effect via either the toolbar button or the Insert menu.
- **Automations → run log** is destroyed when the user navigates between automations; output appears lost.
- **Data → welcome cards** are unresponsive for 3–8s during SQLite init with no disabled/loading state on the cards themselves.

## What works well (don't regress)
- App-switching via the rail / bottom tab bar is fast and the active state is clear.
- Calendar month/week/agenda views, Slides core editing loop + inspector, Data's in-browser SQLite + Chinook demo, and the Editor's core formatting are all genuinely functional.
- Backup's encryption warning is honest and prominent; Automations' three trigger types are honest about what a browser tab can actually do.
- Mobile generally shows one app at a time (more coherent than the desktop Workspace).
