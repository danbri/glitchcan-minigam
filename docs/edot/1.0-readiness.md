# edot — 1.0 readiness audit

Goal: *a world-class, decentralized, mobile-first Cloud Office suite — usable,
useful, consistent, familiar, tested, standards-compatible, web-component based.*
Honest status against each dimension (✅ solid · 🟡 partial · ⛔ open). Kept
current as the refinement lands.

## ✅ Web-component based
Every app is a custom element (`edot-editor/data/slides/calendar/mail/maps/
groups/files/connections/backup/automations/projects`), composed in one shell
(`index.html`) over a shared kernel. Renderers (`lucid-*`) are components too.
No framework; Light-DOM house style; ES modules, no build step.

## ✅ Standards-compatible
WAI-ARIA menu bar / menus / combobox palette; OIDC + **PKCE**; GitHub **Contents
API**; **ICS/iCalendar**; **XMPP/MIX** (XEP-0369/0405) with **SCRAM-SHA-1** vs the
RFC 5802 vector; **RDFa** semantics; **DOCX/ODF/PPTX/PDF/MD/HTML** I/O; OPFS +
**File System Access**; real `inkjs`. RDF/Turtle ontology emission.

## ✅ Decentralized
Fully client-side, no backend; data stays on device unless you connect a remote.
**Every catalogued storage backend is now live** and connects through one
`ResourceSource` interface: OPFS (device), local folder (File System Access),
**GitHub** (Contents API), **WebDAV** (Nextcloud/ownCloud/mod_dav), **Solid pod**
(LDP), and **S3 / S3-compatible** (AWS/MinIO/R2/B2, signed client-side with
**SigV4** — verified against AWS's published vector). Groupware over **XMPP/MIX**
with a **live calendar** pubsub node. Identity: OIDC/PKCE client (tested) + a local
demo identity.
🟡 Remaining only: live (non-demo) sign-in needs a provider **client-id** (a
2-minute user step); every remote's live *network* round-trip is verified at the
request-shaping/crypto level, not end-to-end (standing headless rule).

## ✅ Mobile-first (hardened this pass)
Rail flips to a bottom bar; one app at a time; Workspace panes become sub-tabs.
Menus **clamp within the viewport** (no off-screen spill); the top bar **scrolls
the menu bar and pins the login** at narrow widths; a visible **🔍 palette
button** makes every command touch-reachable (no keyboard needed). Audited: no
horizontal overflow / page errors on editor, slides, calendar, connections,
groups at 360–375px.
🟡 Remaining: real-device pass on the WebGL-heavy Maps/3D and Data (SQLite) apps.

## ✅ Consistent
One **command registry** across 11 apps + an **ontology**; VS-Code-style menu
contribution points; the ⌘K palette and menus share one command source. Editor
**toolbar ↔ Format/Edit/Insert menus ↔ ⌘K** are now at parity (bold, italic,
underline, strike, headings, lists, quote, code, indent, align, link, image,
RDFa, clear). One unified **Connections** storage layer for every "Save to…".

## ✅ Familiar UX
Word/Docs-style **File · Edit · Insert · Format · View · (Actions) · Help**;
document title bar; My documents + autosave; Open (Examples/Research/file/URL);
Save to… / Export; standard shortcuts **⌘B/I/U**, **⌘Z/Y**, **⌘F** (editor Find),
**⌘K** (palette), **⌘N / ⌘⇧O** (new / my documents).

## ✅ Useful
13 apps with real data: Bristol/OSM geo, ICS feeds, RSS/Atom, live XMPP demo,
SQLite/CSV/N-Quads data, slides/docs with media import, projects (.zip bundles),
encrypted backup. Cross-app graph: Data→Editor/Slides, Maps/Calendar/Slides→
Groups, Maps/Calendar→Data, everything→any storage.

## ✅ Usable
Opens to a welcome document; autosaves; accessible menus; honest empty-states; a
**first-run tour** (re-openable via Help ▸ Take the tour) introduces the apps,
⌘K/🔍, Save-anywhere, and the privacy model. Sign-in offers a clearly-labelled
**local demo identity** so the OIDC → Connections flow is usable before any
client-id is configured.
🟡 Remaining: a real provider client-id for live (non-demo) sign-in.

## ✅ Tested
**48 headless suites** (Playwright/Chromium + pure-Node), one runner with CI exit
codes; crypto/protocol verified offline (SCRAM vs RFC 5802, GitHub request
shaping vs a fake Contents API, store bridge vs a fake store).
🟡 Remaining: the E2E workflow isn't in CI yet (the GitHub App lacks the
`workflows` permission — see WORKFLOW-SETUP.md); live network / WebGPU / WebXR
paths are not CI-checked, by the standing headless rule.

## Top open items for 1.0 (ranked)
1. **Real provider sign-in** — one configured client-id (Google/Microsoft).
   *(User action: register an app; paste the public client-id. Plumbing done.)*
2. **E2E suite into CI** — *blocked: the GitHub App lacks the `workflows`
   permission (WORKFLOW-SETUP.md); needs a maintainer to move the template in.*
3. A MIX **shared-files** capability (optional; calendar is live, storage was
   correctly dropped as an over-claim).

All eight core dimensions are now ✅ except the two items above, which are a user
action and a permission grant respectively — not code the suite is missing.
