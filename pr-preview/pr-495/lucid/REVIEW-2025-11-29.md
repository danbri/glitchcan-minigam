## Executive Summary

The Lucid SDF-CSG system is a **well-architected, browser-based 3D rendering engine** that uses Signed Distance Fields (SDF) and Constructive Solid Geometry (CSG) to build scenes declaratively in JSON, compiling them to WebGL fragment shaders for real-time raymarched rendering.

**Strengths:**
- Clean separation of concerns (loader → codegen → renderer)
- Expressive JSON scene format with animation expressions
- Production-ready demos with 20+ templates
- Mobile-friendly with touch controls
- Good performance through careful GLSL generation

**Areas for Enhancement:**
- Node editor UI remains a stub (documented in ASSESSMENT.md)
- Some primitives have simplified SDF approximations
- No optimization/inlining passes for generated GLSL

## Component Analysis

### 1. JSON Loader (`core/json-loader.js`)

**Purpose:** Parse JSON scene definitions into an intermediate representation (IR).

**Supported Node Types:**
| Category | Types |
|----------|-------|
| Primitives | `sphere`, `box`, `torus`, `cylinder`, `capsule`, `ellipsoid`, `plane` |
| CSG Operations | `union`, `subtract`, `intersect`, `smoothUnion`, `smoothSubtract`, `smoothIntersect` |
| Modifiers | `transform`, `group`, `material`, `mirror`, `radial`, `repeat` |
| References | `ref` (to `defs`) |

**Key Functions:**
- `loadJsonScene(json)` - Main entry point
- `processNode(node, registry)` - Recursive node processing
- `processValue(value)` - Handles constants, arrays, and expressions
- `processTransform(transform)` - Parses translate/rotate/scale

**Expression System:**
```javascript
// Variables
{ "var": "time" }  // → IR: { type: 'var', name: 'time' }

// Expressions
{ "expr": "sin", "args": [{ "var": "time" }] }
// → IR: { type: 'expr', op: 'sin', args: [...] }

// Nested
{ "expr": "add", "args": [1.0, { "expr": "mul", "args": [0.3, { "expr": "sin", "args": [{ "var": "time" }] }] }] }
```

**Strengths:**
- Clean recursive processing
- Supports inline transforms on primitives
- Maintains ref→def relationship for expansion

**Potential Improvements:**
- Parameter override in refs is TODO
- Could add validation for malformed scenes

### 2. GLSL Code Generator (`core/json-codegen.js`)

**Purpose:** Convert IR nodes to GLSL fragment shader code.

**Generated Structure:**
```glsl
// 1. Custom uniforms (if any)
uniform float u_customVar;

// 2. Primitive SDF functions
float sdSphere(vec3 p, float r) { ... }
float sdBox(vec3 p, vec3 b) { ... }
// ... etc

// 3. Helper functions
float smin(float a, float b, float k) { ... }
vec3 rotX(vec3 p, float a) { ... }
vec3 rotY(vec3 p, float a) { ... }
vec3 rotZ(vec3 p, float a) { ... }
vec3 rotQ(vec3 p, vec4 q) { ... }           // Quaternion rotation
vec3 rotAxisAngle(vec3 p, vec3 axis, float angle) { ... }

// 4. Generated helper functions (per CSG operation)
vec4 union_0(vec3 p) { ... }
vec4 subtract_1(vec3 p) { ... }

// 5. Main scene function
vec4 g_df_scene(vec3 p) {
  return ...;
}
```

**Key Design Decisions:**

1. **Returns `vec4` not `float`**: Each SDF node returns `vec4(distance, r, g, b)` to carry color through CSG operations.

2. **O(n) CSG Color Selection**: Uses sequential comparisons instead of nested ternaries:
   ```glsl
   // Good (O(n) code size)
   vec4 nearest = c0;
   nearest = nearest.x < c1.x ? nearest : c1;
   nearest = nearest.x < c2.x ? nearest : c2;
   return nearest;

   // Bad (exponential code size)
   return c0.x < c1.x ? (c0.x < c2.x ? c0 : c2) : (c1.x < c2.x ? c1 : c2);
   ```

3. **Helper Functions per CSG**: Each union/subtract/intersect generates a named helper function, keeping the main expression clean.

4. **Transform Composition**: Translations are additive, rotations follow priority order:
   - `rotateQ` (quaternion) takes precedence
   - `rotateAxis` (axis-angle) next
   - `rotate` (Euler XYZ) default

**Rotation Support (v0.6.0):**
```json
// Euler angles (degrees)
"transform": { "rotate": [45, 0, 0] }

// Quaternion [x, y, z, w]
"transform": { "rotateQ": [0, 0.7071, 0, 0.7071] }

// Axis-angle
"transform": { "rotateAxis": { "axis": [1, 1, 0], "angle": 60 } }
```

**Supported Expressions:**
| Op | GLSL |
|----|------|
| `add` | `(a + b)` |
| `sub` | `(a - b)` |
| `mul` | `(a * b)` |
| `div` | `(a / b)` |
| `sin/cos/tan` | `sin(a)` etc. |
| `min/max` | `min(a, b)` |
| `neg` | `(-a)` |
| `clamp` | `clamp(a, b, c)` |
| `smoothstep` | `smoothstep(a, b, c)` |

### 3. Raymarcher (`mayfly/raymarcher.js`)

**Purpose:** WebGL rendering with raymarching.

**Features:**
- **Orbit Camera**: Spherical coordinates (theta, phi, distance)
- **Ground Plane**: Checkerboard pattern at y=-1.5
- **Volume Render Mode**: Accumulates density near surfaces
- **Edge Rendering**: Fresnel-based silhouette darkening
- **Configurable**: Max steps (150), max distance (50), surface epsilon (0.001)

**Shader Pipeline:**
```
Vertex Shader (fullscreen quad)
           │
           ▼
Fragment Shader
  ├─ Inject g_df_scene() from codegen
  ├─ sdGroundPlane() for ground
  ├─ calcNormal() using central differences
  ├─ raymarch() with up to 150 steps
  └─ Lighting: ambient + diffuse + specular
```

**Camera Math:**
```javascript
getCameraPosition() {
  return [
    distance * sin(phi) * sin(theta),
    distance * cos(phi),
    distance * sin(phi) * cos(theta)
  ];
}
```

**Performance Considerations:**
- Device pixel ratio handled
- Resize listener for responsive canvas
- Step size multiplier (0.9) for safety margin

## Performance Characteristics

### GLSL Code Size
- Each CSG operation generates a helper function: ~10-20 lines
- Union of N children: O(N) code
- Nested CSG: Linear in tree depth
- **Avoids exponential ternary explosion**

### Shader Complexity Warnings
From `CLAUDE.md`:
> **DO NOT** create voxel-style models with many small boxes.
> O(n) SDF evaluations per ray step × ~100 steps × HD resolution = GPU meltdown.

Recommended limits:
- Union/subtract: ≤8 children
- Total primitives: 10-20 for mobile
- Use symmetry operators (mirror, radial, repeat) to multiply cheaply

### Rendering Performance
- 150 max raymarch steps
- 0.001 surface epsilon
- Ground plane adds ~1 SDF eval per step
- Volume mode: fixed step size, more expensive

## Conclusion

The Lucid SDF-CSG system is a **well-designed, production-ready** tool for creating real-time 3D graphics through declarative JSON scenes. The architecture is clean, the feature set is comprehensive for its scope, and the demos showcase the system's capabilities effectively.

**Key Strengths:**
- Declarative JSON format that's easy to read and write
- Full animation expression system
- Multiple rotation methods (Euler, quaternion, axis-angle)
- Symmetry operators for efficient scene construction
- Mobile-first design with touch controls

**Primary Gap:**
The node graph editor remains unimplemented (stub only), which limits accessibility for non-technical users. The ASSESSMENT.md provides a solid roadmap for this feature.

**Overall:** Ready for creative use, with clear paths for enhancement.
